# Reliability update — 2026-10-12

## Plan

1. Persist each physical Judge request before dispatch and its public response before score parsing. Fail closed on journal errors; keep provider reasoning and credentials out of the journal.
2. Stop dispatching new Cases after three consecutive, typed model-network failures in completion order. Drain active Cases; record the remaining queue without assigning scores to unstarted Cases.
3. Include bounded UTF-8 head/middle/tail previews of large text deliverables, with byte offsets and source hashes. Binary, restricted and invalid UTF-8 samples remain indexes. Previews never imply complete content coverage.

## Validation

Run targeted request lifecycle, concurrent dispatch and file-preview regressions, then `pnpm run verify`. Use synthetic files and mocked model responses; no paid Agent evaluation or server deployment is part of this change.

## Behavior and limits

- **Request journal / 请求日志**: Default application Judges use owner-only durable files under `judge/requests`. Bodies can contain private references; these files are local evaluation data. A failed write blocks new calls on that instance. A remaining `STARTED` entry means billing is unknown, not zero. Parsed provider JSON is archived as public message content and usage; malformed provider envelopes retain a fixed failure code, not raw thinking/error text.
- **Dispatch stop / 停止派发**: Three consecutive Cases with trusted model transport errors, or all expected labels failing with recognized network error codes, stop new dispatch. Ordinary task failures, partial Judge failures, authentication errors and context-limit errors do not count. Already-started Cases finish. `run.json` records `dispatchStop` and `unstartedCaseIds`; no zero scores are created for pending Cases. No automatic resume is introduced.
- **Large text / 大文本**: At most three 4 KiB UTF-8 windows are included with byte ranges and SHA-256. Total serialized preview content remains within the existing Case budget. Whole-file hashing uses bounded memory; originals larger than the existing archive limit remain `NOT_ARCHIVED`. Binary files, restricted files, undecodable samples and files exceeding the 4 GiB preview scan limit remain indexes. A preview does not establish whole-document correctness.

## Verification outcome

`pnpm run verify` passes: 153 contract tests, 5 workbench tests and 5 import tests, plus TypeScript checks, build and publication-boundary checks. Regression coverage includes journal-before-fetch ordering, malformed paid responses, audit failure without rebilling, symlink rejection, dispatch stop/drain in both pipelines, and byte-exact UTF-8 previews. No real model or Agent calls were made.
