## 字段现状

| 核对内容 | 已有依据 | 能确认什么、缺什么 |
| --- | --- | --- |
| 实际题单 | `plan.json.queue[].datasetId/caseIndex/caseId`；DSH 与共享适配器均在 Case 开始前写入计划 | 可查当时选题顺序；队列 `caseId` 按位置生成，不能当作永久原题身份。DSH 另需按 `run.json.caseResults[].executionRunId` 区分父批次和子运行 |
| 原题身份 | 完整 `report.json.case.caseId`、`case.question.id/version`；`scope.caseId` 关联队列题次 | 原题身份与队列题次不是同一个 ID。必须同时核对数据集、归属和内容；标题或版本相同不足以证明同题 |
| 题目与输入内容 | `case.contentDigest`、`case.inputs[].sha256`；公开报告保留这些值 | 现有加载器可对当前完整题包重新计算并比对。输入摘要不提供原文件字节，文件已缺失时不能凭摘要恢复输入 |
| 私有参考与规则 | `case.grading.referenceDigest`、`labels[].contentDigest`；实际评分记录另有 `labelDigest` | 参考原文被隔离，摘要与冻结标签可保留比较依据；不能靠摘要还原私有参考。Judge 未运行时不能假设一定有评分记录中的标签摘要 |
| 评测选择与范围 | `run.json.evaluationConfig`，共享适配器 `plan.json.evaluationConfig`，报告 `evaluationMode`；实际清单看 queue | 可区分 FULL/EFFECT 和当时的选择请求；COUNT/ALL 的原参数不等于实际原题单，不能重新自动选题后称为同题复测 |
| 已知 Agent 配置 | `inspection.json`、报告 target/inspection 中的版本、组件/插件、权限等；`run.json.compatibility.fingerprint` 保留兼容性身份 | 已保存的具体字段可比较。指纹中的配置摘要可区分合成模型参数变化，但只有哈希不能还原模型名/接口地址，也不能将整体摘要差异直接归因为模型变化 |
| 评测模型配置 | 部分 `scores[].model`、`plan.model/datasetMatchModel`；当前设置由 ModelSettings 单独读取 | 有模型名记录不等于全量策略/端点快照。通用 Pi 路径未统一保存原目标 model 的可解释值；当前 Planner/Judge 设置不是历史快照，未调用或旧记录缺字段时继续未知 |

Case 总摘要来自完整加载结果，包含种子输入、已解析评分参考等；公开投影会移除输入正文/私有参考，但保留原摘要。**不能对脱敏后的公开 Case 重算摘要，再把它当作原始 Case 摘要核对。** 总摘要变化表示加载内容或条件不同，不单独证明变化来自正文、参考或其他某一因素。

## 磁盘记录与当前读取能力的区别

- 当前 `ControlResults.get()` 摘要投影没有返回完整 queue、原选择请求、原题身份和 Case 内容摘要；输入只投影目标路径。因此当前历史摘要本身不足以准备可靠的同题请求。
- 已有受控单题报告 JSON 读取路径会经 `parseVerifiedReportDocument → publicReportDocument` 返回公开报告，原题身份及摘要仍在。这是可以复用的现有能力，**不能把摘要投影缺字段误写成磁盘没有字段，或据此直接扩展协议**。
- 本次只验证报告验真/公开投影函数及只读历史读取，没有启动 HTTP 服务或 App，不声称完成实际页面/接口联调。
- 共享适配器的目标快照较简；DSH 有更丰富的 TargetSnapshot/Artifact 引用，但引用存在不证明对应字节仍可读、匹配或足以解释所有配置。须逐记录验证，不跨路径统一宣称全部支持。

## 阻塞与下一步边界

1. **没有逐记录核验的原题匹配证据时阻塞。** 只保存位置索引，或缺完整报告、内容摘要、实际输入/必要参考的旧记录，不能承诺同题。现有字段足够的记录也要先验真，再与当前题包匹配，不能直接复用旧索引。
2. **没有完整历史配置值时，配置变化只能部分说明。** 版本、组件、权限、指纹和已知模型字段按实际材料列出；目标/Planner/Judge 模型、端点或策略缺失就标未知。若验收要求完整同条件复测，该记录保持阻塞；不根据当前设置推断旧值。
