## 开发和打包

[package.json](../package.json) 声明 Node.js 最低版本 `>=22`、pnpm 固定为 `11.24.0`；当前 [CI](../.github/workflows/ci.yml) 使用 Node.js 24，本机已有验证使用 24.19.0，接班建议使用 24.x。声明最低版本不等于各个 Node 22 版本都已实测。先核对 `node --version`、`pnpm --version`，再按锁文件安装。

```sh
pnpm install --frozen-lockfile
pnpm run verify
node --test workbench/lib/model-settings.test.mjs
```

上述检查使用合成材料，不需要真实 Agent 或模型密钥。下列启动及打包命令按任务授权选择执行，不是接班时必须全部运行：

```sh
pnpm run desktop
pnpm run desktop:pack
pnpm run desktop:dmg
```

`desktop` 先构建和暂存再启动原生窗口；`desktop:prepare` 只构建并暂存资源。直接启动普通 App 会读取当前用户环境；需要合成验收时应使用隔离材料与受控服务，不能把临时 Chromium 数据目录当作模型/Agent 凭据隔离。源码高级工作台的独立配置与启动步骤见 [原生源码指南](NATIVE_SETUP.md)，不要为桌面界面验收照抄其中的真实评测步骤。

`desktop:pack` 生成当前 Mac 架构的 `.app`，`desktop:dmg` 生成安装镜像，均位于 `artifacts/mac/`。默认使用临时（ad-hoc）签名封装应用及其嵌套组件，并在签名后执行 `codesign --verify --deep --strict`，避免打包修改破坏 Electron 原始签名后被报告损坏。临时签名仅证明包内文件完整，不提供 Apple 认可的开发者身份，也不等于公证；首次打开仍可能被 macOS 拦截。对外发行并通过默认 Gatekeeper 检查，需要配置 Developer ID Application 证书、Apple 公证凭据并完成公证。不得将 `spctl` 显示 `override=security disabled` 的本机结果视为分发验收通过。应用、Dock 和安装镜像使用白色圆角方形的 EvalDock 小马头图标（`desktop/assets/icon.png` / `icon.icns`），四周保留透明边距；1024 像素 PNG 与包含各尺寸的 ICNS 使用同一图案。打包检查会核对应用图标文件与声明，防止回退到 Electron 默认图标。

图标白底宽高固定为画布的约 80.5%（1024 像素画布、824 像素圆角底、四周各 100 像素留白），与本机 Chrome 图标的可见尺寸比例一致。保留原始小马图案 `desktop/assets/pony-source.png`；需要重新生成图标时，在装有 Xcode Command Line Tools 的 Mac 上执行 `pnpm run desktop:icon`，使用固定几何模板同时更新 PNG 与 ICNS。

打包脚本只选取 Git 跟踪的运行资源、明确列出的桌面文件和编译产物；不会携带源码目录中的运行结果、下载题库、用户 Agent 配置或密钥。内置 Node 运行时用于 EvalDock，自行安装的 Agent 及 Python、浏览器等题目依赖仍需另行准备。

### 干净安装包

资源暂存前检查当前源码的发布边界，暂存后检查实际资源字节，打包后再次检查 `.app` 内的运行资源与 `app.asar`。嵌入的评测历史、任务目录快照、个人路径、凭据、缓存和未声明的资源会让构建失败；编译后的契约测试不进入安装包。首次创建工作空间的本地题库为空（0 道题），Agent 配置为空，不附演示题、评测记录、Trace、报告或真实题库。合成演示题仅保留在源码及开发样例中；安装包从 `desktop/empty-library/` 初始化空目录。

可单独检查最终应用并生成文件摘要清单：

```sh
node scripts/audit-desktop-runtime.cjs artifacts/mac/mac-arm64/EvalDock.app artifacts/mac/release-files.json
```

同一台 Mac 打开新安装包仍会保留已有用户数据。检查独立工作空间时，可用新的 Chromium 用户目录启动应用：

```sh
preview_dir="$(mktemp -d -t evaldock-clean-preview)"
open -n artifacts/mac/mac-arm64/EvalDock.app --args "--user-data-dir=$preview_dir"
```

此检查保留原工作空间，模型凭据和已安装 Agent 仍属于当前系统用户。完全首次使用须在新 macOS 用户或干净 Mac 中验收；签名、公证和跨版本更新验证仍按下文要求完成。不要为制作干净安装包删除用户工作空间，后续升级继续保留配置、题库和结果。

## 首次运行

1. 打开 App，在「设置」填写 Planner / Judge 接口及密钥。使用 Pi、Hermes、OpenClaw 或 LangGraph 时，还需在「被测 Agent 模型」单独填写 DeepSeek API Key；这些适配器当前使用 DeepSeek。办公 Agent 的账号在原应用中登录，DSH 继续使用自己的服务配置。
2. 「我的 Agent」自动扫描本机安装，显示品牌图标、版本和接入状态。点击「重新扫描」更新结果；支持自动接入的安装可点击「接入评测」，立即加载并检查运行条件。LangGraph 可点击「接入 LangGraph」填写项目目录、Python、Graph 工厂入口、模型、实际工具和路径模式；其他自定义路径仍可通过「高级配置」补充；DSH 的服务与插件管理保留在高级工作台，Agent 卡片不作为工作台入口。
3. 首次安装没有本地题目。「测试集」默认加载固定版本的 BenchDock 完整目录，展示名称、题量和下载状态；目录校验后缓存在本机，可离线浏览。点击卡片「下载题库」准备该测试集的公开题目与输入文件，显示真实进度并支持取消、重试。下载通过校验和备份流程加入本地题库，保留已有题目；完成后可以选择题目评测。也可导入完整本地题库文件夹或 ZIP。自动选题默认使用本地题库；在评测弹窗选择「完整线上目录与本地题库」后，先匹配目录并仅准备所需题目，再进入正式评测。打开选题弹窗不下载题目。
4. 点击「开始评测」，选择可连接的 Agent，默认由 Planner 自动选择 1 道题，可在「本次题数」选择 1–3 道。需要原有规模时主动选择「标准规模（最多 70 题）」；也可以手动选择具体题目。在「评测记录」查看进度、取消任务或打开已有报告。

App 关闭时会请求取消本应用启动的评测并等待收尾。启动页面尚未加载完成时主动退出，不再弹出因窗口关闭产生的“启动失败”提示；真正的启动失败仍会提示。不要在任务中退出 App。缺少 Agent、登录、模型配置或外部依赖时，评测会被阻止或报告具体运行失败；下载题库不代表已具备所有执行条件。

WorkBuddy、千问办公和豆包办公的「启动连接」从主界面和高级工作台使用各自同一启动入口。启动桌面 Agent 时移除评测后台的 `ELECTRON_RUN_AS_NODE`；千问和豆包还只传递白名单中的基础环境变量。评测后台、DSH 与 Pi 等 Node 运行入口仍使用所需的 Node 模式。启动请求成功后仍按实际连接、调用接口和登录状态显示结果，不把请求受理当作可评测。

千问已经以普通方式打开、尚未启用连接端口时，「启动连接」会请求所选安装正常退出，等待最多 30 秒后用连接参数重新打开，保留原应用数据。千问若弹出退出确认框，请确认后继续；取消或超时会提示重试，不强制结束主应用。运行中的 EvalDock 评测、未确认的清理和多个主应用实例会阻止重启；孤立后台进程不会被当作另一个主窗口。已连接但未登录时保持「需要登录」，完成客户端要求的账号登录及授权后再评测。豆包仍需先正常退出未启用连接端口的实例，再点击「启动连接」。两者只有实际接口检查完成才返回连接结果，按钮会显示连接进度并在失败后恢复；详见[办公 Agent 启动说明](../adapters/OFFICE_AGENTS.md#启动)。

DSH Web 的新后台进程会从本机启动链接交换服务认证，兼容同源根路径的 `/`、`./` 或绝对地址跳转；异源地址和其他路径仍被拒绝。认证材料留在后台，不返回前端。检查现有服务不要求重启 DSH，也不改变已有插件配置。

## 本地数据与题库

工作空间位于 `~/Library/Application Support/EvalDock/workspace/`：

- `config/`：用户 Agent 配置，升级不覆盖。
- `datasets/`：当前题库，升级不覆盖。
- `dataset-history/`：每次导入前的题库备份。
- `var/evaluation-results/`：评测结果。
- `var/batch-runtime/`、`var/workbench/`：执行目录和任务状态。
- `desktop.log`：服务诊断日志。

模型密钥沿用现有的 `~/.config/evaldock/models.env`（0600 权限），与源码版共用。其余桌面运行数据独立于源码目录。程序代码随 App 启动更新到工作空间。

Pi、Hermes、OpenClaw 和 LangGraph 的被测模型密钥单独保存到 `~/.config/evaldock/agent-model.env`（0600 权限），不向前端返回密钥，也不向被测 Agent 传递 Planner / Judge 密钥。新设置优先于继承的 `DEEPSEEK_API_KEY` 和旧的 `~/.dsh/.env`；旧配置仍可作为回退，保存新设置不会修改它们。密钥留空保留已有值；CLI Agent 评测运行中禁止修改。保存后重新检查就绪状态，无需手动创建 DSH 配置目录。

导入选择包含 `catalog.md` 的完整文件夹或 ZIP，格式与仓库 `datasets/` 一致。ZIP 可直接包含题库，也可套一层文件夹；先解压到临时目录，验证后沿用同一导入事务。目前是**整体切换**，不是合并；旧题库保留在历史目录。导入拒绝符号链接和非普通文件，限制 4 GB / 100000 文件；ZIP 另拒绝加密、路径越界、重复路径和完整性错误。使用核心加载器验证题目、输入和评分参考后再切换。评测、下载或线上准备过程中禁止导入。`evaldock-import.json` 记录导入时间、题量和 SHA-256；现有评测报告继续保存题目内容摘要。

测试集页显示评分参考就绪题量、可评分题目的维度覆盖和逐题参考状态。已有完整私有题库可通过「导入题库」接入；加载器验证 `private/` 下的参考材料，执行结束后交给现有 Judge，不需要新增评分服务。选择「完整流程」保留过程证据，未测到或证据不足的维度仍不评分。Agent 接口、JSON/HTML 报告与工作台投影不返回参考原文；新报告保留参考摘要，旧报告在读取时投影，磁盘原记录保持不变。

题库仅由服务端加载，前端只读取目录元数据和已安装题目的公开任务要求，不返回评分参考答案。线上目录与公开文件使用 `config/benchdock-pilot.json` 固定的发行版本，验证清单、目录和输入文件 SHA-256，复用通过校验的缓存与导入备份流程。目录含公开任务和仅来源记录；仅来源记录不能从线上目录下载，已经导入的本地题目仍可选题。按测试集下载采用 input/work/output 文件交付契约与基础交付、成本、推理标签；核对过的试点保留其配置，其他任务保留外部环境提示，不自动安装服务或推断上游原生运行环境。下载失败、取消或本地题库发生并发修改时保留原题库。模型密钥不会发送给 Hugging Face；下载使用现有 HTTPS 代理环境变量或 macOS 系统 HTTPS 代理。公开题缺少私有评分材料时保留 `UNASSESSABLE`，不会变成零分。题目声明的 Python 等执行依赖仍需另行准备。其他 Agent 的完整图形化配置仍需补充。主界面不提供虚构运行数据。

## 线上自动匹配

选择「完整线上目录与本地题库」时，先检查所选 Agent 的实际接口与登录状态，再把目录名称、标签、公开题量及运行条件提示交给 Planner。仅来源记录不参与匹配；已有导入题库及评分参考优先保留，不以线上内容覆盖。准备阶段只补齐推荐题量所需的公开题目，全部待下载文件合计最多 2 GB；再次匹配可补充已下载测试集中的缺少题目。准备记录保存在 `var/online-selection/`。

这是两个规划阶段：线上匹配负责准备题库；正式评测仍由现有 Planner 从当前本地题库选题，推荐结果不保证与最终题目完全一致，两次请求均可能产生模型费用。弹窗显示阶段并可取消，准备失败不会启动评测；已经完成安装的少量题目保留供后续使用。外部服务、账号与工具仍需按任务要求准备，准备成功不代表环境或评分参考就绪。

少量模式在提交时固定 Agent、评测模式和题量，将相同的 `COUNT` 配置传给准备及正式执行；准备阶段还会在下载前拒绝超过该题量的计划。提交期间选题控件不可修改，失败或取消后可重新选择。题目不足时保留现有 Planner 的校验结果，不扩大量级或自动切换标准规模。此限制不改变测试集卡片的按子集下载入口；小样本验收使用少量模式或手动选择已在本地的题目。

## 应用更新

菜单「EvalDock → 检查更新」分别显示检查结果、下载与待安装状态。「查看发布版本」打开官方 GitHub Releases。Developer ID 签名的已安装版本会在启动后检查稳定版更新；用户选择下载，下载完成后选择「安装并重启」。评测、题库准备或导入未结束时阻止安装，关闭 App 不会自动安装更新。更新保留工作空间配置、题库及结果，下载失败保留当前应用。

开发版及临时签名版显示自动更新不可用，可通过发布页手动下载安装。正式自动更新需要相同发行身份签名、公证和真实的更新发布材料。维护者用 `pnpm run desktop:release` 本地生成 DMG、ZIP 与更新元数据，不自动发布；先在环境中配置 `EVALDOCK_SIGNING_IDENTITY`（Developer ID Application）及 Apple 公证凭据。设置以 [electron-builder 更新说明](https://www.electron.build/v26/docs/features/auto-update/)为准，凭据留在本地或 CI Secrets。实际跨版本升级、失败恢复与干净 Mac 安装仍需在准备好的环境验收，契约测试不替代这些检查。

## 本机 Agent 发现

启动主界面时自动扫描，结果缓存至手动「重新扫描」。扫描 `/Applications`、`~/Applications`、PATH、Homebrew、用户级 CLI 目录和最多 20 个 NVM Node 安装。同时检查 `~/Agents/pi` 的源码构建或 npm 安装，以及 `~/Agents/openclaw` 的 npm 安装与独立 Node 运行时。只检查已知应用/命令入口和安装元数据，不执行扫描到的命令、不启动 Agent、不读取登录凭据。CLI 符号链接按真实路径去重；不同安装位置分别显示。无权限或损坏的安装不会让整个扫描失败。

可识别 DSH、Pi、OpenClaw、Hermes、WorkBuddy、千问办公、豆包办公、Codex 和 Claude 的常见安装入口。Codex / Claude 只显示发现结果，目前没有评测适配器。LangGraph 需要用户指定实际 graph 入口，不能仅凭 Python 环境推断。Pi 同时识别 `@mariozechner/pi-coding-agent` 和 `@earendil-works/pi-coding-agent` 包名。OpenClaw 的 Trace 采集支持桌面工作空间中包含空格的路径。其他非标准安装路径可能需要高级配置。

Claude 卡片分别标注 `Claude Code（CLI）` 和 `Claude（桌面）`，并逐个显示对应安装的版本；两种安装同时存在时不会取其中一个版本代表全部。CLI 只从已知包元数据读取版本，桌面只读取应用元数据；已发现入口但元数据损坏或缺少版本时，保留安装并显示“版本未读取”及原因，可点击「重新扫描」更新。扫描不会运行 `claude --version`，也不会因发现安装而提供评测入口。

「接入评测」只接受本次重新检查后仍存在的安装，不覆盖已有配置，不启动评测、不打开调试端口，也不改变登录状态。Pi、Hermes、OpenClaw 仍使用现有适配器的模型和凭据策略；发现 CLI 并不代表可复用其所有原生模型配置。办公 Agent 的调用与事件接口、登录及连接由适配器检查，版本号不作为准入门槛。

已接入的 CLI Agent 缺少被测模型密钥时，卡片提供「配置模型」入口，直接定位设置页对应表单。点击「开始评测」先检查 Planner/Judge 模型，缺少时进入设置；模型条件满足而本地题库为空时进入测试集并提示导入。有本地题目但没有就绪且空闲的 Agent 时，弹窗禁用提交并提供「前往我的 Agent」。设置、Agent 和测试集页面也可独立访问；未安装 Agent 时仍需用户先安装，再重新扫描。空库不会直接触发线上选题或真实执行。

DSH 未安装、Web Profile 缺失或配置损坏时，高级工作台保留「连接待确认」和配置检查提示，阻止 DSH 的启动、停止、重启、插件修改及评测；其他 Agent 和已有评测记录仍可读取。主界面也能读取磁盘归档，同一目标的同一轮记录只展示一次，不改写历史报告。

Agent 卡片统一显示待安装、已发现或可评测状态。已配置目标可展开「查看检查详情」，读取当前目标、检查状态、版本、原因码及可用的检查时间；未知原因也保留原因码，并提供「重新检查」。需登录时提示在原应用完成登录后重新检查，清理未确认时引导查看评测记录。重新检查只更新实际状态，不启动评测、登录或清理会话。

同品牌存在多个安装时，卡片动作、状态和版本绑定当前显示的配置目标；优先显示目标检查版本，仅在精确匹配同一安装时使用标注为「扫描」的版本。无法对应时显示版本未读取，不借用其他安装的版本。发现安装不等于可评测。安装路径和配置详情不在卡片展示，已有高级配置仍可从设置访问。

## 产品页面

概览页的评测介绍区仅保留「开始评测」按钮；测试集可从侧栏或题库统计卡片进入。

测试集卡片和选题详情不展示测试集长介绍，保留名称、评分维度、题量和选题入口；逐题详情继续展示实际任务要求。题库说明保留用于自动选题和搜索。

测试集页合并线上目录与本地题库，支持「全部」「待下载」「已在本地」筛选。目录总题量、本地题量、评分参考就绪题量分别统计；下载状态不作为评分就绪状态。只有本地题目能勾选或提交评测。公开内容下载完成后可以直接选题；混合测试集中仅来源记录仍不加入选题范围。

切换筛选或搜索时，结果数量的变化不会移动筛选按钮；窄窗口下筛选按钮保持成组排列。

题库卡片分别展示下载与校验安装阶段。下载按文件字节显示百分比、数据量和文件数，复用缓存计入已准备的数据量，失败重试不重复累计。安装显示复制文件数、已校验题量与校验百分比；准备和保存阶段显示动态进度条。下载完成后仍明确显示安装进度，直到真实安装完成。

评测详情在逐题结果上方展示「能力雷达图」，按本轮各维度的有效 Case 权重汇总，保留原始量表。只有一两个评分维度时，也会用现行 15 个维度作参照显示得分点；本轮覆盖至少 3 个维度时使用本轮维度绘图。未覆盖、待评分、证据不足和 Judge 错误保留各自状态，不补为零分；不同评分标准不合并，缺失轴之间不绘制填充区域。此图展示本轮任务表现，不代表未测能力的结论。

桌面侧栏使用 EvalDock 官方小马头与文字组合 Logo，随应用运行资源一起打包。主界面采用紧凑工作台样式：白色侧栏与顶栏、浅灰背景、低饱和绿色强调色和细边框矩形面板；概览铺满可用宽度，保留评测介绍与入口、统计及最近记录，不展示三步引导卡片和记录区提示；成功、错误与运行状态保留独立的语义色。设置页铺满内容区，Planner 与 Judge 并排展示，使用紧凑表单；窄屏自动改为单列。

概览展示就绪数量、运行中任务和最近记录。测试集支持搜索、任务预览、逐题勾选和跨测试集选题；选择结果以 SELECTED 方案提交。评测记录支持状态筛选、搜索、逐题评分和回答预览、日志、取消和已有 HTML 报告。评分保留各自量表，零分与证据不足分开显示，不合并不同标准的分数。

历史记录缺少批次日志时，题数与完成、失败、取消计数从已有 `run.json` 的逐题结果读取；只有 Job 成功或结束状态时，不推算所有题目已经完成。部分完成仍保留剩余题量，正在执行的 Case 继续展示实际阶段。读取只更新界面投影，不回写历史 Job、报告或评分。

高级工作台的归档入口与主界面复用同一份只读记录投影，不依赖额外的归档服务，也不触发 Agent 接口检查、登录或任务。某类记录无法读取时保留其他记录并显示对应诊断；请求失败时保留已加载的记录。

高级工作台的测试集目录与主界面读取同一份当前本地题库。页面重载后，等目录成功读取再恢复仍存在的数据集和题目定位；读取失败保留保存的选择供重试，已删除或不属于所选数据集的题目会清除定位。点击「刷新目录」更新题目增删与修改，并清除已失效的详情缓存；刷新失败时保留已加载目录并提示重试。题目详情展示公开任务、运行条件、输入清单和评分参考状态，不返回私有参考原文或题目源文件。安装包中的静态题目目录继续为空。

## 桌面应用启动

启动办公应用时移除子进程继承的 `ELECTRON_RUN_AS_NODE`，避免应用进入后台 Node 模式；主界面为已接入但未连接的千问/豆包提供「启动连接」入口。

## WorkBuddy 接口准入

WorkBuddy 的版本号用于记录，不再作为评测准入白名单。连接时检查调用桥、事件传输基础接口和登录状态；会话创建、任务提交、事件回传及清理由实际运行验证。未连接或接口缺失会显示具体原因，基础检查通过不等同于所有任务已通过兼容验收。

千问与豆包同样按接口检查准入，豆包额外检查本机执行环境。千问检查 RPC 请求与响应入口及流式消息、完成、错误事件的订阅入口。执行环境检查失败会清除可评测状态。DSH、Pi、Hermes、OpenClaw、LangGraph 同样不按版本号拒绝评测。Pi 通过无任务 RPC get_state 预检；Hermes 与 OpenClaw 检查实际执行子命令的必要参数；LangGraph 在临时目录中加载配置的 Graph 并检查 stream / astream，随后释放上下文，不调用 Graph 执行任务。DSH 继续验证服务与会话接口，主界面也检查模型配置、配置重启需求及忙碌状态。CLI 参数检查不能保证运行期事件格式兼容；所有适配器继续在真实运行中检查完成、采集和收尾。这不表示每个新版本均已完成真实评测验收。

## LangGraph 表单接入

「我的 Agent → 接入 LangGraph」提供 DeepAgents、Agent Service Toolkit 原始聊天 Graph、文件工具 Graph 和自定义模板。模板只预填配置，不安装软件或修改 Graph；文件工具模板需要本机已经准备好独立的 `evaldock_files_entry.py`。原始聊天 Graph 没有文件工具，执行完成不代表交付文件成功。

保存前检查目录、Python 可执行权限和入口文件；保存后由适配器导入 Graph 检查 stream/astream 接口，不执行题目。每个具体 Graph 单独显示卡片、接入状态和评测入口。同一 Python 与入口重复提交保留原配置；不同入口分别保存，历史记录不变。模型凭据继续由本机 Agent 凭据配置提供，不在此表单收集。

## 评测前兼容性检查

正式评测在投递题目前会执行兼容性验收，工作台与直接 CLI 共用入口。首次检查会创建合成小任务，验证文本、独立会话、文件交付、工具证据和取消清理；豆包还验证后台子任务。检查会消耗被测 Agent 自身的调用额度，但不调用 Planner／Judge。日志以 `[evaldock:compatibility]` 展示分项进度。

接口可连接与兼容性验收通过仍是不同状态。检查返回兼容、不兼容、待判定或环境阻塞；只有本次所需能力全部通过才继续评测。缺少登录、未能触发目标行为或清理未确认时保留证据并停止，不产生零分代替失败。

验证记录保存在工作空间的 `var/compatibility/`，绑定客户端、驱动、配置和验收套件指纹，有效期为 24 小时。命中记录后仍做轻量接口检查；版本或关键配置变化会重新验收。源码工作树可用 `pnpm run compatibility --list` 查看入口（已安装应用的工作空间使用 `node adapters/compatibility/cli.mjs --list`），通过 `--target-id` 指定目标、`--force` 强制复验，详见[适配器说明](../adapters/README.md#version-compatibility-admission)。DSH Web 使用原有真实执行器参加验收；DSH Headless 使用独立进程及会话归档专项验收，只有所需检查通过后才准入，且不复用 Web 凭证。源码命令可用 `--descriptor /path/to/local-target.json` 指定本机 DSH 配置。

本轮没有自动编码适配、自动修复客户端或后台升级。兼容性检查通过不等于真实评测、Judge 评分和报告已经通过验收。

## 自动选题的输出校验与补试

Planner 正常生成有效选题结果时只请求一次模型。结果未通过 JSON、数据集、题量或说明字段校验时，保留原输入和约束，将具体校验原因交给模型重新生成，最多补试两次；全部请求共用设置中的 Planner 超时预算和取消信号。日志显示补试次数与校验原因。

选题理由仍须为非空的 1–500 字符，提示词建议控制在 100–200 字符，详细依据写入 evidence。持续失败仍会在投递题目前停止，不自动放宽校验或改为手动选题；网络和 HTTP 错误不参与这项格式补试。

## 不同 Agent 版本的接入

DSH、Pi、Hermes、OpenClaw、LangGraph、WorkBuddy、千问办公和豆包办公按实际接口匹配已实现的协议，不维护版本号白名单。安装版本、选中的协议和实际评测结果分别记录；升级后指纹变化会重新执行兼容性验收。未知接口或证据格式会停止接入并给出原因，不能据此承诺所有未来版本。

Pi 根据实际帮助信息选择参数，并兼容新旧密钥引用语法；密钥仅通过被测进程的环境提供。Hermes 在旧版缺少 JSON 输出接口时读取本题独立状态目录的原生会话数据库。LangGraph 检查真实 Graph 的 stream/astream，首次导入超时单独显示，不把它直接判成版本不兼容。

千问和豆包支持选择安装路径及本机连接端口。扫描可接入应用程序目录或用户应用程序目录中的对应产品；不同安装路径分别保存，不覆盖已有配置。连接须与所选安装一致，启动读取应用清单中的实际可执行文件。豆包的已知模块按导出接口检查和定位，旧模块编号只作提示；接口缺失或不唯一时仍需补适配。

本轮在 `evaldock-dev` 的真实验证范围见[支持情况](../adapters/SUPPORT.md#2026-10-12-开发虚拟机回归)。按用户要求，千问只验证已登录的 1.2.1，豆包跳过真实评测；不能把这两项写成所有版本均已实测。
