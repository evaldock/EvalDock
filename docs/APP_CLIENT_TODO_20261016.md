## 本地保存与影响边界

1. `clone/fetch` 是下载；保存文件和 `git commit` 是本地操作。它们不会更新 GitHub 共享分支。新目录使用独立 `.git`，原项目文件不会因为在新目录编辑而改变。
2. 新目录的 `origin` 下载地址保留；推送地址设为 `disabled://local-only`，另设 `push.default=nothing`，阻止常规误推送。它不防止主动绕过配置、改用其他 URL 或通过网页/API 写入。将来确需推送时先明确分支与范围，再恢复推送配置。
3. **不推送不等于所有操作都无影响。** 默认启动 App 会使用同一系统用户的 EvalDock 工作空间；模型设置和 CLI Agent 密钥分别共用 `~/.config/evaldock/models.env`、`agent-model.env`。只换源码目录或 Chromium 用户数据目录，不能保证凭据和外部 Agent 隔离。启动、设置修改、导入、评测、SSH 同步和部署需要各自的范围控制。
4. 本轮按用户“先拉代码、给 TODO/任务卡、本地保留”的范围，覆盖 [AGENTS.md](../AGENTS.md) 的默认 VM 同步行为：未连接或同步 VM，未推送或发布，也未操作共享工作空间、配置或已有 App。未来执行仍沿用本轮边界，直到明确改变范围。
5. 原目录保留，最新源码及本轮文档另存于新目录；完成后做本地文档 commit 和额外 Git bundle 快照。bundle 只保存已纳入 Git 的提交与引用，不含忽略数据、未保存编辑缓冲区、密钥、题库和运行结果；也不是异机备份。后续改动要保存并及时本地提交，不能认为它们会自动进入今天的快照。

本轮原目录核对、下载/CI/Release 元数据、本地提交和快照结果保存在代码目录之外的 `outputs/app-client-20261016/` 与 `backups/app-client-20261016/`，不进入安装包。
